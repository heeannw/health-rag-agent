# 2. 매칭·데이터 담당 (담당: 가은)

> 기존 "예측모델 엔지니어" 역할에서 내용이 바뀌었습니다. 개인 건강 위험도 예측은 의료법 리스크로 범위에서 제외되었고, 대신 사용자 조건에 맞는 복지 혜택/의료기관을 매칭해 추천하는 역할로 전환되었습니다.

## 담당 업무
- 사용자 조건(연령대, 지역, 자가선언형 소득 카테고리 등) 입력 처리 — 정확한 소득 금액 등 개인정보는 수집하지 않음
- 복지 혜택 조건 매칭 로직 — 혜택별 공식 선정기준과 사용자 조건을 비교해 해당 가능한 혜택 추천
- 지역별 의료기관/보건소 데이터 가공 — 지도 화면·병원/보건소 상세 화면에 쓰일 구조화 테이블 구축
- 혜택·기관 매핑 테이블 설계 (벡터DB가 아닌 관계형/구조화 데이터로 관리)
- 관련 공공데이터 API 연동
- 매칭 결과 분석 — 조건별 추천 품질 검증

## 데이터
- 원희(`data-rag/`)가 이미 수집한 welfare_central / welfare_local / hospital / ltc_institution / dementia_center 수집기 결과를 재사용 권장 (중복 수집 방지 — `data-rag/collectors/` 코드 공유받아서 활용)
- 지역 코드 체계(시도/시군구 코드) 통일 필요 — `data-rag/collectors/ltc_institution.py`의 `SIDO_CODES` 참고

## 협업 포인트
- 원희: 매칭 대상 복지·기관 데이터 스키마 공유
- 소현: 매칭 결과를 지도/혜택추천 화면에 렌더링할 API 응답 포맷 협의
